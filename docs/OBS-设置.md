# OBS 设置

这个服务是 **OBS 推流 → 网页观看**。这份文档只讲推流端怎么填，以及为什么必须这么填。

一句话版本：

| 项 | 值 |
|---|---|
| 服务 | **WHIP**（不是「自定义」RTMP） |
| 服务器 | `http://43.142.33.45:8443/whip/share01?k=<推流令牌>` |
| 认证 / Bearer 令牌 | **留空、不要勾**（令牌已经写在地址的 `?k=` 里了） |
| 最大 B 帧 | **0** |
| 音频 | Opus（选 WHIP 就天然是 Opus，不用你操心） |

观众看的是 `http://43.142.33.45:8443/?k=<观看令牌>`，两个令牌不是一回事：推流令牌只给 OBS，
别发出去；给观众发带观看令牌的那条链接。

---

## 0. 三条「填错就翻车」

### 0.1 走**明文 http**，不是 HTTPS

**这台机器没有域名，也就没有真证书。** MediaMTX 只能用自签证书，而 **OBS 会静默拒绝自签证书** ——
它不会弹一句「证书不受信任」，只会连不上，日志里也未必直说。

所以这一版就是**全链路明文 http**，地址老老实实写 `http://43.142.33.45:8443/...`。
在 IP 阶段假装用 HTTPS 只会浪费时间；等以后有域名、签发真证书了再换 HTTPS + 443，其余不用动。

### 0.2 服务必须选 **WHIP**

选「自定义」走 RTMP 也能推上去，但音轨会变成 AAC —— 服务端得把它转成 Opus 才能在浏览器里发出去，
**音质就在这一步坏掉**。WHIP 的音轨原生就是 Opus，服务端全程不转码。

（RTMP 不是完全不能跑，观众会被自动切到 HLS 兜底，延迟 2-4 秒。能用 WHIP 就别用 RTMP。）

### 0.3 **B 帧必须是 0**

浏览器实现 WebRTC 时**刻意不支持** H.264 里的 B 帧。推流端开了 B 帧，观众那边典型症状是
**只出声不出画**（或者画面对着不动），而且报错信息一点线索都没有。

好消息：实测 OBS 的 WHIP 输出本来就强制 `b-frames: 0`。但这一项在界面上不显眼、换模式时又容易被带回去，
所以下面还是显式写一遍，并且用 `check-obs.mjs` 从日志里核对**实际生效**的值。

## 1. 推流地址（设置 → 直播）

| 项 | 值 |
|---|---|
| 服务类型 | **WHIP** |
| 服务器 | `http://43.142.33.45:8443/whip/share01?k=<推流令牌>` |
| 认证 | **不要勾**；Bearer 令牌留空 |

- 地址从 `.env` 里的 `PUBLISH_TOKEN` 取值（部署方给你的那条就是拼好的，直接用）。
- 房间号 `share01` 是**服务端固化**的：nginx 只认这一个路径。写错房间号会直接 404。
- 令牌不对会 401；`?k=` 后面不要带空格、不要换行 —— 从聊天/文档里复制最容易带上隐藏字符。

> 地址里那个 `/whip/share01` 是**对外**的路径。服务端内部转发到 MediaMTX 时会改写成别的路径，
> 那是 nginx 的事，你不需要知道。

## 2. 码率预设（先选一套，再谈别的）

出口带宽只有 **4 Mbps**，这是这个项目最硬的约束，所有码率都是围着它算的。

**预算口径**（下面两张表都是这么算的）：

```
出口占用 = (视频码率 + 音频码率) × 人数 × 1.07     ← 1.07 是协议/封装开销
总出口    4 Mbps，预留 15% 余量 → 目标 ≤ 3.4 Mbps
```

### 2.1 默认档：3-4 人（绝大多数时候用这套）

| 项 | 值 |
|---|---|
| 分辨率 | 1920×1080 |
| 帧率 | **20 fps** |
| 编码器 | NVENC H.264 |
| 速率控制 | CBR **700 kbps** |
| 关键帧间隔 | **2 秒** |
| Profile | high |
| 音频 | Opus **48 kbps 单声道** |
| 每人出口 | **约 0.80 Mbps** |

| 人数 | 出口占用 | 说明 |
|---|---|---|
| 1 | 0.80 Mbps | |
| 2 | 1.60 Mbps | |
| 3 | 2.40 Mbps | |
| **4** | **3.20 Mbps** | ← 目标线 3.4 Mbps 下最多 4 人 |
| 5 | 4.00 Mbps | 已经吃满 4 Mbps 总出口，没有余量 |
| 6 | 4.80 Mbps | 超了 |
| 10 | 8.00 Mbps | 超一倍 |

### 2.2 画质优先档：1-2 人

人少的时候可以把码率全砸给画面，屏幕上的小字明显更实。

| 项 | 值 |
|---|---|
| 分辨率 | 1920×1080 |
| 帧率 | 30 fps |
| 速率控制 | CBR **1400-2500 kbps**（一般 1500-1800 就够） |
| 关键帧间隔 | **2 秒** |
| 音频 | Opus **96 kbps** |
| 每人出口 | **约 1.6-2.8 Mbps** |

| 人数 | @1400 kbps | @2500 kbps |
|---|---|---|
| 1 | 1.60 Mbps | 2.78 Mbps |
| 2 | 3.20 Mbps | 5.56 Mbps ✗ |
| 3 | 4.80 Mbps ✗ | 8.33 Mbps ✗ |

> 每人 1.6-2.8 Mbps 是按 `(视频+音频)×1.07` 算的；只算视频、不算音频的话是 1.50-2.68 Mbps，
> 也就是别处写过的「1.56-2.7 Mbps」那一档 —— 同一个量级，差在音频算不算进去。
> `node scripts/load-test.mjs` 会把这两套档位的换算直接打出来，以它为准。

### 2.3 懒人版：一键装 profile

懒得手抄可以跑 `./scripts/install-obs-profile.ps1`（用法见 `docs/OBS-profile-安装.md`）：
它把上面这两套预设直接渲染成 OBS profile 装到 `%APPDATA%\obs-studio\` 下，装完在
OBS 菜单「配置文件」里选一下就能推。两套的参数和本文一致，只有一处小差别：
**它的音频是 Opus 64 kbps 立体声**（本文默认档写的是 48 kbps 单声道）。

那点差别不影响结论：64 kbps 音频下每人约 0.82 Mbps，4 人合计 3.27 Mbps，仍在 3.4 Mbps 目标线内。
装完照样要跑一次 `node scripts/check-obs.mjs` 核对**实际生效**的值 —— profile 文件写对了，
不等于 OBS 真的读了（见 3.2）。

### 2.4 5-10 人：先解决出口带宽，别调 OBS

4 Mbps 分给 10 个人，每人只有 400 kbps；扣掉 7% 开销和 48 kbps 音频，
**视频实际只剩约 320 kbps**。这个码率下 1080p 的屏幕文字必然糊成一团，
再怎么调 OBS 的编码参数都没用 —— 瓶颈不在编码，在出口。

真要上 10 人，只有两条路：

1. **加带宽（推荐）**：把实例改成**按流量计费**，峰值能到 100 Mbps。
   成本心里有个数：10 人 × 1 Mbps × 1 小时 = 10 Mbit/s × 3600 s = **约 4.5 GB** 流量。
2. **降规格**：分辨率降到 1280×720、帧率 15、码率 350 kbps/人 —— 文字更糊，但人数能上去。

先把带宽解决掉，上面那两张表里的人数才谈得上。

## 3. 输出设置（设置 → 输出 → 输出模式选「高级」）

### 3.1 编码器参数

| 项 | 值 | 为什么 |
|---|---|---|
| 编码器 | **NVIDIA NVENC H.264**（配置键名 `obs_nvenc_h264_tex`） | 有 N 卡就用它，省 CPU。没有 N 卡就用 x264，其余项照填 |
| 速率控制 | **CBR** | 直播要可预测的码率；VBR 在画面剧烈变化时会冲高，出口直接爆 |
| 比特率 | 见上面两张表（700 / 1400-2500 Kbps） | |
| 关键帧间隔 | **2**（秒） | OBS 默认 250 帧，1080p20 下就是 12.5 秒：刚进来的人要黑屏等到下一个关键帧，HLS 兜底更惨，它必须等到关键帧才能切分片 |
| 最大 B 帧 | **0** | 见 0.3 |
| Profile | **high** | 兼容性和画质的平衡点 |
| 预设（Preset） | `p5` | 再慢没必要，瓶颈在带宽不在编码 |
| 调优（Tuning） | **Low Latency（`ll`）** | NVENC 的低延迟档，顺带关掉 multipass |
| 前向预测（Look-ahead） | **取消勾选** | 预分析 8 帧是实打实的额外延迟 |
| 心理视觉调优（Psycho Visual Tuning） | **取消勾选** | 这类针对**自然画面**的优化会让屏幕文字发虚、抖 |
| 重复头部（Repeat Headers） | **勾上** | 新观众进来不用等下一个关键帧才拿到 SPS/PPS |

### 3.2 附：profile 里的 `streamEncoder.json` 必须是**扁平**格式

如果要预置/脚本化 OBS 的 profile，改的是 `%APPDATA%\obs-studio\profiles\<profile>\streamEncoder.json`。
这个文件的**顶层就是扁平键**，不是按编码器 id 嵌套：

```json
{
  "rate_control": "CBR",
  "bitrate": 700,
  "keyint_sec": 2,
  "preset": "p5",
  "tune": "ll",
  "multipass": "disabled",
  "profile": "high",
  "lookahead": false,
  "psycho_aq": false,
  "bf": 0,
  "repeat_headers": true
}
```

两个坑（旧项目都踩过，改这个文件前先读完）：

1. **嵌套结构一个键都不会被读。** 写成 `{"obs_nvenc_h264_tex": { ... }}` 这种按编码器 id 包一层的结构，
   OBS 加载时静默忽略全部设置，安安静静用回默认值（10000 kbps / keyint 250 / lookahead 开）——
   界面上完全看不出来，只有日志和 `check-obs.mjs` 能戳穿。
2. **键名是 `tune`，不是 `tuning`。** 而 OBS **日志**里打印的偏偏是 `tuning` —— 两边名字不一样，
   别照着日志改 JSON。

判断键名对不对的唯一可靠办法：**在 UI 里改一次，然后看 OBS 自己往这个文件里写了什么。**
别猜。（改完 profile 要**重启 OBS** 才会重新扫描。）

## 4. 视频设置（设置 → 视频）

| 项 | 值 |
|---|---|
| 基准（画布）分辨率 | 1920×1080 |
| 输出（缩放）分辨率 | 1920×1080 |
| 缩小方法 | Lanczos |
| 常用 FPS 值 | **20**（默认档）/ 30（画质档） |

**码率不够时，先降帧率，别降分辨率。**

屏幕共享的画面是大片纯色 + 锐利文字边缘，和摄像头画面完全不一样：

- **降帧率**：30 → 20 → 15 fps，看文档、讲代码完全够用，省下的码率全部变成清晰度
- **降分辨率**：1920×1080 → 1280×720 之后，小号字体直接糊掉，观众得眯着眼看 —— 这是最亏的一刀

手里机器吃力（编码跑不满）就降分辨率，那是另一回事；**带宽不够**时降帧率。

## 5. 音频（设置 → 音频）

| 项 | 值 | 为什么 |
|---|---|---|
| 采样率 | **48 kHz** | WebRTC 的 Opus 就是 48 kHz。设 44.1 kHz 会被重采样，白白损失音质 |
| 声道 | 单声道（默认档）/ 立体声（画质档） | 讲人声单声道足够，48 kbps 单声道比 96 kbps 立体声更实在 |
| 音频比特率 | **48 kbps**（默认档）/ 96 kbps（画质档） | 要放音乐再往上加 |

- 选 WHIP 时音频天然是 Opus，服务端原样转发，全程不转码。
- 要放电脑里的声音，得加「应用程序音频采集」或「音频输出采集」，不然别人只听得见你说话。

## 6. 来源

窗口共享用 **「窗口采集」**，捕获方式选 **「Windows 10 (1903 及以上)」**：

- 这个模式走 Windows Graphics Capture，能抓到大部分带硬件加速的窗口（浏览器、播放器）
- 老旧的 `BitBlt` 模式抓到的是黑屏
- 抓不到某些窗口（比如部分游戏、部分播放器的受保护内容）就改用「显示器采集」

## 7. 推之前先验一遍

1. 点「开始推流」，等 OBS 状态变成推流中
2. 跑一遍参数核对（读的是 **OBS 自己的日志**，不是猜的）：

```powershell
node scripts/check-obs.mjs                      # 默认档：700 kbps / 20 fps
node scripts/check-obs.mjs --preset=quality      # 画质档：1400-2500 kbps / 30 fps
node scripts/check-obs.mjs --bitrate=700 --fps=20 --keyint-sec=2   # 自己指定
```

它会逐项打 `✓/✗`：编码器是不是 NVENC H.264、**B 帧是不是 0**、是不是 CBR、码率/帧率对不对、
关键帧间隔够不够短、音频是不是 Opus、WHIP 会话有没有连上、停播时 DELETE 有没有被拒，
顺手还会检查 profile 里的 `streamEncoder.json` 是不是扁平格式。

3. 打开观众页 `http://43.142.33.45:8443/?k=<观看令牌>`，应该 1 秒内出画面
4. 人多了想看看服务端扛不扛得住：

```powershell
node scripts/load-test.mjs        # 默认 4 路
node scripts/load-test.mjs --n=10
```

5. 想把整条链路（推流 → 出画 → 音轨是 Opus → 降级 HLS → 鉴权）一次验完：

```powershell
node scripts/e2e.mjs
```

它会自己合成一路 WHIP 推流去测，不需要 OBS 在场，也不需要你分享屏幕。

## 8. 排查

| 现象 | 先看这里 |
|---|---|
| OBS 报连不上 | 地址是不是 **`http://`** 开头（不是 https）、路径 `/whip/share01`、端口 8443；腾讯云安全组和主机 ufw 都要放行 **8443/tcp**（WebRTC 媒体还要 **8189/udp**） |
| OBS 报鉴权失败 / 401 | `?k=` 后面的推流令牌和 `.env` 里的 `PUBLISH_TOKEN` 是否一致；有没有多余空格；房间号是不是 `share01` |
| 推上去了但观众**没画面只有声音** | **B 帧是不是 0**（见 0.3）、关键帧间隔是不是 2 秒 |
| 观众有画面没声音 | OBS 音频采样率是不是 48 kHz；「应用程序音频输出采集」加没加 |
| 观众卡、画质差 | 降帧率（不是降分辨率），或把码率往下调；`node scripts/load-test.mjs --n=10` 看出口占用 |
| 人一多就糊 | 出口只有 4 Mbps —— 见 2.4，先解决带宽 |
| 观众页打不开 | 观众链接是 `http://43.142.33.45:8443/?k=<观看令牌>`，别拿推流令牌去开 |
| 想知道实际码率/分辨率 | 观众页上的状态块会显示；或者跑 `node scripts/e2e.mjs` 看「服务端零转码」那一节 |
